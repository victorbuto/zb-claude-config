# Новые инструменты работы с сайтами и гайды по источникам

**Обновлено:** 2026-07-31
**Назначение:** список инструментов, которых нет в текущем trend-research (SKILL.md, sources.md, conditional-sources.md, trend_sources.py), с указанием, какую именно дырку каждый закрывает.
**Описание:** сравнение с текущим стеком скилла (Exa/Tavily/WebSearch, Reddit RSS+shreddit, HN Algolia, GitHub REST, Polymarket Gamma, Telegram MCP + TGStat, gtrends-parser, yt-parser). Разбито по функции, а не по популярности.

## Что уже есть и что не покрыто

Покрыто: поиск (Exa, Tavily, WebSearch), 4 условных API-источника, Telegram, свои парсеры Google Trends и YouTube, большой каталог сайтов с правилами запроса.

Не покрыто:
1. Извлечение содержимого произвольной страницы (URL → чистый текст).
2. Работа с PDF-отчётами, а это формат почти всего каталога big3/big4.
3. Сайты за логином и JS (Statista, Euromonitor, LinkedIn, Kantar).
4. Мониторинг вместо разовых заходов.
5. Историческая глубина — что было на сайте и в сообществе раньше.
6. Новостные и научные API как источники сигнала.

## A. URL → чистый текст

| Инструмент | Что даёт | Ключ | Комментарий |
|---|---|---|---|
| [Jina Reader](https://jina.ai/reader/) | Префикс `https://r.jina.ai/<URL>` возвращает страницу в markdown | не нужен | Самый дешёвый способ. Одна строка в bash, работает из любого скилла |
| [Trafilatura](https://trafilatura.readthedocs.io/) | Извлечение основного текста + метаданные (дата публикации, автор, язык) | не нужен | Python/CLI, офлайн. Лучший precision на новостных статьях. Под отраслевую прессу — то, что надо: даёт дату, а она нужна для фильтра свежести |
| [Crawl4AI](https://github.com/unclecode/crawl4ai) | Локальный краулер, markdown-first, под LLM-пайплайны | не нужен | ~68K звёзд. Бесплатно, без лимитов, но анти-бот-защиту решаешь сам |
| Firecrawl MCP | `scrape` / `map` / `crawl` / `extract` со схемой + `monitor` | есть у тебя | **Уже подключён в окружении, но не прописан в скилле.** Самый быстрый выигрыш |
| Tabstack MCP | `extract.json` по своей JSON-схеме, `extract.markdown` | есть у тебя | Тоже уже подключён. Полезен, когда нужны конкретные поля (цена, дата, объём рынка), а не весь текст |

## B. PDF и документы

Критично: каталог отчётов big3/big4, `trend-reports-catalog-2026-07-17.md` (205 PDF) и все открытые отчёты Nielsen/Circana — это PDF, а не HTML.

| Инструмент | Что даёт | Комментарий |
|---|---|---|
| [Docling](https://github.com/docling-project/docling) (IBM) | PDF/DOCX/PPTX → структурированный markdown **с таблицами** | Таблицы — главное. В отчётах консалтинга цифры лежат именно в них |
| [MarkItDown](https://github.com/microsoft/markitdown) (Microsoft) | Любой файл → markdown | Легче и быстрее Docling, но хуже с таблицами. Годится для быстрого прогона пачки файлов |

## C. Сайты за логином и JS

| Инструмент | Что даёт | Комментарий |
|---|---|---|
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | Агент управляет реальным браузером, сессия сохраняется между запусками | Под Statista, Euromonitor, Kantar, LinkedIn — там, где у тебя есть доступ, но обычный fetch не проходит. Сохранение сессии — ключевой пункт: без него агент логинится каждый раз и ловит блокировки |
| [browser-use](https://github.com/browser-use/browser-use) | То же, но агентно: задача текстом, а не сценарий кликов | Когда путь до данных заранее неизвестен |

## D. Сайт → поток (мониторинг вместо разовых заходов)

| Инструмент | Что даёт | Комментарий |
|---|---|---|
| [RSSHub](https://github.com/DIYgod/RSSHub) | 5000+ маршрутов: превращает сайт, YouTube-канал, Telegram, GitHub releases, Weibo, Bilibili в RSS | ~41K звёзд. Селф-хост в один клик на Railway, который у тебя уже есть. Закрывает отраслевую прессу и авторов без RSS |
| [Miniflux](https://miniflux.app/) / [FreshRSS](https://freshrss.org/) | Читалка-бэкенд с API, чтобы ленту читал агент, а не ты | Превращает трендвотчинг из разового прогона в накопление |

## E. Историческая глубина

| Инструмент | Что даёт | Ключ | Комментарий |
|---|---|---|---|
| [Wayback CDX API](https://github.com/internetarchive/wayback/tree/master/wayback-cdx-server) | Все снимки URL: таймстемп, статус, MIME, content digest | не нужен | Диффы во времени: как менялись цены, позиционирование, продуктовая страница конкурента. Для трендвотчинга это прямое доказательство сдвига, а не мнение |
| [Arctic Shift](https://github.com/ArthurHeitmann/arctic_shift) | Исторический Reddit 2005→2026, ~120K запросов/час, без авторизации | не нужен | Твой `trend_sources.py` берёт только свежее через RSS+shreddit. Это добавляет ретроспективу: когда тема впервые всплыла и как росла. PullPush — запасной вариант, но медленнее и с провалами |
| [Google Books Ngrams](https://books.google.com/ngrams) | Частота слова/фразы в книгах за 200+ лет | не нужен | Прямо под твои видео про историю идей: видно, когда понятие вошло в оборот |

## F. Бесплатные API-источники, которых нет в trend_sources.py

| Источник | Что даёт | Ключ | Под какой вопрос |
|---|---|---|---|
| [GDELT](https://www.gdeltproject.org/data.html) | Глобальная база новостных событий и тона медиа, обновление каждые 15 минут, выгрузка в BigQuery | не нужен | Самая большая дырка в твоём стеке: новостного API нет вообще. Даёт объём и тональность освещения темы по странам во времени |
| [Wikipedia Pageviews API](https://wikimedia.org/api/rest_v1/) | Просмотры любой статьи по дням и странам | не нужен | Дешёвый прокси внимания, дополняет Google Trends. Хорошо ловит момент, когда тема выходит за пределы ниши |
| [OpenAlex](https://docs.openalex.org/) | 250M+ научных работ, 90M+ авторов | не нужен, без лимитов | У тебя в каталоге только Elicit и Consensus как сервисы. Это API: можно считать рост числа публикаций по теме за годы — самый ранний сигнал тренда |
| [Crossref](https://api.crossref.org/) / [Semantic Scholar](https://api.semanticscholar.org/) / [arXiv](https://info.arxiv.org/help/api/) | То же поле, разные срезы | не нужен | arXiv — под AI и tech, где препринт опережает статью на год |
| [Google Trends API (alpha)](https://developers.google.com/search/blog/2025/07/trends-api) | Официальный доступ к Trends | по заявке | Твой `gtrends-parser` работает на неофициальном пути. Стоит держать в виду как замену |
| Product Hunt GraphQL API, YC company data | Запуски и батчи как структурированные данные | Product Hunt — да | У тебя они перечислены как сайты, но без тулинга |
| pypistats, npm-trends, GitHub star history | Скорость принятия инструмента | не нужен | Дополняет твой GitHub REST: не «сколько звёзд», а «как быстро растёт» |

## G. Гайды по источникам

Это то, чего у тебя нет как класса: не список сайтов, а поддерживаемые внешние каталоги, куда можно ходить за источником под новую тему.

- [Bellingcat Online Investigation Toolkit](https://bellingcat.gitbook.io/toolkit) — 170+ инструментов по категориям (гео, соцсети, финансы, архивы). Внутри есть [OSINT Tools Map](https://bellingcat.gitbook.io/toolkit/more/all-tools/osint-tools-map) — постранововой список бизнес-реестров, судебных баз и кадастров. Прямо полезно для проверки конкурентов и рынков за пределами РФ
- [GIJN Research Guides](https://gijn.org/) — методические гайды по глубокому интернет-поиску от сети расследовательской журналистики
- [jivoi/awesome-osint](https://github.com/jivoi/awesome-osint) и [Astrosp/Awesome-OSINT-List](https://github.com/Astrosp/Awesome-OSINT-List) — живые кураторские списки инструментов
- [awesome-public-datasets](https://github.com/awesomedata/awesome-public-datasets) — открытые датасеты по доменам, дополняет Google Dataset Search

## Приоритет внедрения

1. **Jina Reader + Trafilatura** — одна строка и одна библиотека, закрывают «URL → текст с датой». Без этого агент читает только сниппеты выдачи.
2. **Docling** — открывает 205 PDF-отчётов из твоего каталога, которые сейчас лежат мёртвым грузом.
3. **GDELT + Wikipedia Pageviews** — два бесплатных API в `trend_sources.py`, закрывают новостной и «внимание» сигнал, которых там нет.
4. **Wayback CDX** — превращает утверждение «рынок сдвинулся» в диффы страниц с датами.
5. **RSSHub на Railway** — переводит отраслевую прессу из разового поиска в накопительный поток.

Остальное подключать под задачу: Playwright MCP — когда упрёшься в логин, Arctic Shift — когда нужна ретроспектива сообщества, OpenAlex — когда тема имеет научный фронт.
