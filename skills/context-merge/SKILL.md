# Context Merge

Превращает несколько разрозненных файлов с рекомендациями в один файл лучшего
контекста — прозрачно и под ручным контролем пользователя. Главный принцип:
**итог собирается только из оригинальных текстов, без выдуманных примеров и
рекомендаций.**

## Когда применять
Пользователь даёт 2+ файла (рисёрч, теория, skills, how-to) и хочет отобрать /
смержить из них релевантный контекст в один файл.

## Жёсткие принципы (нарушать нельзя)
- **Без искажений.** В итоговом файле — только дословный оригинальный текст
  (для «принять») или честное слияние оригиналов (для «смержить»). Не
  придумывать примеры, не «улучшать» формулировки, не дополнять.
- **Прозрачность.** Пользователь видит весь контекст в HTML и сам решает
  чекбоксами, что идёт в работу. По умолчанию всё «Пропустить».
- **Slice без потерь.** Нарезка сохраняет рекомендацию вместе с её примером и
  пояснением.

## Рабочая папка и вывод
- Создай slug задачи (kebab-case, по сути целевого контекста), например
  `agent-researcher` или `jtbd-context`.
- Рабочая папка результата:
  `/Users/fixed/Documents/ZB CLOUD 3600/CLOUD ZB (3600)/Researches/context-merge/<slug>/`
  Создай её. Туда кладёшь `slices.json`, `analysis.json`, `review.html` и
  итоговый файл. (НЕ внутрь папки скилла.)

## Workflow

### Шаг 1 — Входы и целевая задача
1. Собери у пользователя пути ко всем входным файлам (или путь к папке — тогда
   возьми из неё все текстовые файлы).
2. Задай ОДИН уточняющий вопрос: **для какого агента / задачи готовим контекст
   и что считать релевантным?** Это `{TARGET}` — критерий отбора. Без него не
   нарезай.

### Шаг 2 — Параллельная нарезка (slice method)
- Прочитай `references/slicing-prompt.md`.
- Запусти **по одному субагенту на каждый файл, параллельно** (несколько вызовов
  Agent в одном сообщении, `subagent_type: general-purpose`). В промпт подставь
  `{FILE_PATH}` и `{TARGET}`.
- Каждый агент возвращает JSON-массив блоков. Собери все массивы в один список,
  проверь уникальность `id` (при коллизии — добавь префикс), запиши в
  `<папка>/slices.json`.
- Если блоков подозрительно мало или агент вернул `[]` для большого файла —
  скажи об этом пользователю.

### Шаг 3 — Категоризация
Прочитай все блоки из `slices.json` и сам (без субагентов) сгруппируй:
- **similar** — 2+ блока про одно и то же (дубли/близкие рекомендации).
- **unique** — блок без пары.
Каждый блок входит ровно в одну группу. Похожесть — по смыслу рекомендации, а не
по теме (две рекомендации на одну тему могут быть разными — это не «схожие»).

Напиши `overview` — основные выводы и наблюдения по всему контексту: что
повторяется, где дубли, чего не хватает, какие явные противоречия. Это пойдёт в
шапку HTML.

Запиши `<папка>/analysis.json`:
```json
{
  "overview": "текст выводов (переносы строк допустимы)",
  "groups": [
    {"id":"g1","type":"unique","title":null,"slice_ids":["s1"]},
    {"id":"g2","type":"similar","title":"Тема группы","slice_ids":["s2","s4"]}
  ]
}
```

### Шаг 4 — Сборка HTML
Запусти:
```bash
python3 scripts/build_review.py \
  --slices "<папка>/slices.json" \
  --analysis "<папка>/analysis.json" \
  --out "<папка>/review.html" \
  --title "Контекст для: <TARGET>"
```
Скрипт детерминированно строит страницу: шапка с выводами, карточки (суть +
краткое описание + «показать оригинал»), схожие — визуально в одной рамке рядом,
чекбоксы под каждой единицей (по умолчанию «Пропустить»).

Дай пользователю **полный путь к `review.html`** и попроси открыть его в Chrome,
расставить выбор и нажать «Создать контекст».

Карточки/группы дают такой выбор:
- уникальная: «Принять» / «Пропустить»
- схожие: «Смержить и принять» / «Принять по отдельности» / «Пропустить»

### Шаг 5 — Получение выбора
HTML файл сам не пишет. По кнопке «Создать контекст» он показывает текст выбора
в окне. Пользователь копирует его и вставляет в чат. Формат строк:
- `[ПРИНЯТЬ] s1 | source.md | заголовок` — взять блок дословно
- `[СМЕРЖИТЬ] g2 (s2, s4) — тема` + строки с блоками группы — честно слить
- пропущенные в текст не попадают

### Шаг 6 — Сборка итогового файла
По полученному выбору собери `<папка>/context-<slug>.md`, читая
`original_text` нужных блоков из `slices.json`:

- **[ПРИНЯТЬ]** — вставь `original_text` блока дословно, как отдельный раздел
  с заголовком (`title`). Ничего не меняй в тексте.
- **[СМЕРЖИТЬ]** — объедини `original_text` всех блоков группы в один раздел:
  - сохрани все уникальные мысли и **все примеры** из оригиналов;
  - убери только буквальные повторы;
  - НЕ добавляй ничего от себя, НЕ переписывай формулировки сверх необходимого
    для склейки. Если сомневаешься — оставь оба варианта подряд.
- Порядок разделов — логичный для целевой задачи.
- В начале файла добавь метаданные (по правилам проекта): дата обновления,
  назначение документа, краткое описание, список файлов-источников.

Покажи пользователю путь к итоговому файлу и короткое резюме: что вошло, что
смержено, что пропущено.

## Частые ошибки
- Нарезать без `{TARGET}` → блоки не отфильтрованы по релевантности.
- Перефразировать `original_text` при нарезке или сборке → искажение, запрещено.
- Считать «схожими» блоки на одну тему, но с разной сутью → ложное слияние.
- Сохранять результат внутрь папки скилла вместо `Researches/context-merge/<slug>/`.
