# Методика декомпозиции задачи

Источники: «Точим топор» (В. Буто) + Issue Tree Guide (Crafting Cases). Дубли сведены.

## Содержание
1. Этап 1 — описать задачу (рамка)
2. Этап 2 — определить тип задачи → тип дерева
3. Этап 3 — построить дерево (правила MECE и качества)
4. Чек-лист ошибок
5. Правила приоритизации

---

## Этап 1. Описать задачу

Без рамки дерево решает не ту проблему. Заполнить до построения дерева:

1. **Точка А** — текущее нежелаемое состояние (откуда уходим).
2. **Контекст** — ограничения, сроки, рыночные условия, личные лимиты.
3. **Точка Б** — желаемое *состояние системы*, НЕ конкретное решение.
4. **Метрики успеха** — по чему точно поймём, что задача решена (срок, бюджет, оценка ≥7/10).
5. **Задача** — действие без привязки к методу решения («снять квартиру», не «через риелтора»).
6. **Субъекты** — действующие лица и их мотивации.
7. **Объекты** — ключевые объекты системы и их свойства.
8. **Контекст целого** — задача как часть большей системы и цели.

Если каких-то данных нет — задать пользователю до 3 уточняющих вопросов, не угадывать.

---

## Этап 2. Тип задачи → тип дерева → фреймворк

Сначала определить тип задачи, он диктует, КАКОЕ дерево строить.

| Тип задачи | Дерево | Техника / фреймворк декомпозиции |
|---|---|---|
| Поиск первопричины | **Why-tree** (drivers) | 5 способов MECE; Пирамида Дилтса |
| Увеличение метрики | **How-tree** + Math-tree | формула (Метрика = A × B); воронка по %; сумма сегментов |
| Автоматизация / удешевление | How-tree | производственные принципы, сокращение издержек/времени |
| Сделка / привлечение | How-tree | аудитория → канал → ценностное предложение → воронка |
| Выбор | **Decision tree** (IF-THEN) | варианты × критерии оценки |

**Drivers vs Levers:** drivers = причины (WHY), levers = управляемые рычаги (HOW). НЕ смешивать в одном дереве.

### Три техники построения веток
- **Math tree** — где есть числа: разложить по формуле, по воронке конверсии (%), по сумме сегментов/продуктов.
- **5 способов MECE** — для качественных задач; каждая ветка раскрывается в свою мини-MECE-структуру.
- **Decision tree** — IF-THEN, когда разные сценарии требуют разного анализа (тип «Выбор»).

## Этап 3. Построить дерево

### MECE на каждом уровне
- **Mutually Exclusive** — ветки не пересекаются.
- **Collectively Exhaustive** — ветки покрывают всё, без пробелов.
- Особенно строго на 1-м слое (не-MECE первый слой — фатальная ошибка).

### Принципы построения
- Строить по одной части за раз: определение → 1-й слой → затем каждая ветка вглубь.
- Разделять разные проблемы рано, не сваливать в кучу.
- Каждая дочерняя часть полностью объясняет родительскую ветку.
- Ветки **falsifiable / eliminative** — проверяемы данными, можно подтвердить или исключить.
- Из нескольких возможных MECE-вариантов выбирать самый **инсайтный и релевантный**, не произвольный.
- Прояснять допущения на каждом слое.

### Глубина и остановка
- 2–5 слоёв. Стоп, когда ветки разумно объясняют задачу.
- Углубляться только там, где остаётся вопрос «почему?» или где данные указывают.

## Чек-лист ошибок (избегать)

- ❌ Дерево решает не ту задачу (плохое определение проблемы на Этапе 1).
- ❌ Не-MECE первый слой (пересечения или пробелы).
- ❌ **Aggregator fallacy** — путать «контейнеры» с причинами («больше складов = больше краж»).
- ❌ Решения подмешаны в диагностическое (Why) дерево.
- ❌ Корреляция выдаётся за причинность.
- ❌ Неизмеримые / непроверяемые ветки.
- ❌ Минорная сегментация (география и т.п.) раньше главных причин.

---

## Правила приоритизации (Точка Б критериев успеха)

После построения дерева ответить на главные вопросы пользователя:
- **С чего начать** — тестировать самые вероятные гипотезы первыми (правило 80/20).
- **Что на что влияет** — отметить связи и зависимости между ветками.
- **Приоритеты** — отметить вес/важность ключевых веток (например 🔴 высокий / 🟡 средний / ⚪ низкий).
