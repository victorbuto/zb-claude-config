# Task Decomposition

Раскладывает задачу так, чтобы пользователь понял составляющие, приоритеты и зависимости. Опирается на методику в `references/methodology.md` (MECE, типы деревьев, чек-лист ошибок).

## Вход
Описание задачи от пользователя (текст или файл). Если задача описана скудно — задать до 3 уточняющих вопросов по рамке Этапа 1 (Точка А, контекст, Точка Б, метрики успеха). Не угадывать.

## Workflow

Прочитать `references/methodology.md` перед работой — это основа.

1. **Описать задачу.** Заполнить рамку из 8 полей (Этап 1 методики): Точка А, Контекст, Точка Б, Метрики успеха, Задача, Субъекты, Объекты, Контекст целого.
2. **Определить тип задачи** → выбрать тип дерева и фреймворк (Этап 2: таблица типов). Это определяет структуру дерева.
3. **Построить дерево** по правилам MECE и качества (Этап 3). Проверить себя по чек-листу ошибок. Глубина 2–5 слоёв.
4. **Расставить приоритеты:** с чего начать (80/20), что на что влияет, вес ключевых веток.
5. **Сгенерировать два файла** (см. ниже).
6. **Вывести ответ в чат строго в таком порядке** (см. «Вывод в чат»):
   - тип задачи (одна строка);
   - **само дерево** — вложенный список со всеми ветками и весами 🔴/🟡/⚪ (это обязательная часть, не заменять ссылкой на файл);
   - **только потом** — рекомендации/приоритеты (с чего начать, зависимости);
   - в конце — ссылки на оба файла.

## Вывод в чат

Дерево всегда показывать прямо в сообщении, не прятать в файл. Порядок жёсткий:

1. **Тип задачи** — одна строка.
2. **Дерево** — полный вложенный список (корень → ветки 1-го слоя → подветки) с весами 🔴/🟡/⚪. Узлы короткие. Это ядро ответа.
3. **Рекомендации** — с чего начать (80/20), что на что влияет. Идут ПОСЛЕ дерева, не перемешивать с ним.
4. **Файлы** — ссылки на `.md` и `.txt`.

Никогда не отдавать рекомендации без предварительно показанного дерева.

## Выходные файлы

Создать папку `CLOUD ZB (3600)/Decompositions/<task-slug>/` (slug — короткий уникальный из сути задачи). Если пользователь работает внутри конкретного проекта — положить в папку этого проекта. НЕ перезаписывать существующие файлы.

### Файл 1 — `<slug>-decomposition.md`
Структура:
- **Мета** (дата обновления, назначение документа, краткое описание) — по правилам репозитория.
- **1. Рамка задачи** — 8 полей из Этапа 1.
- **2. Тип задачи и подход** — выбранный тип + почему.
- **3. Декомпозиция (дерево)** — вложенный список + блок Mermaid `graph TD` для визуализации.
- **4. Приоритеты** — с чего начать, зависимости (что→на что), веса (🔴/🟡/⚪).

Для типа «Выбор» дерево строить как decision tree (IF-THEN: варианты × критерии).

### Файл 2 — `<slug>-miro.txt`
Текст с табами для импорта в Miro Mind Map. Формат строго по `references/miro-format.md` (только табы, один корень, без маркеров).

## Критерии качества (самопроверка)
- Дерево **понятное и прозрачное** для чтения — короткие узлы, чистая иерархия.
- **Логичное** на уровне топ-консультантов: MECE на каждом слое, нет ошибок из чек-листа, ветки проверяемы.
- Видно **приоритеты и связи** — пользователь понимает, с чего начать.
